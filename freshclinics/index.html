Under the hood

Retrieval‑augmented generation decides who gets named.

Modern AI search doesn't answer from memory alone. It runs retrieval‑augmented generation (RAG): the prompt is encoded into a dense vector, matched against an index of passages from across the web, and the language model writes its answer conditioned only on the passages that survive retrieval, reranking and corroboration. A company that isn't in that retained context window can't be named, however good it is.

01

Query decomposition and embedding

The prompt is rewritten into sub‑queries ("medical director," "med spa," "US," "best") and each is projected by a transformer encoder into a high‑dimensional vector space, where meaning is measured as distance.

q → E(q) ∈ ℝd
02

Hybrid dense and sparse retrieval

Approximate nearest‑neighbor search over passage embeddings is fused with lexical (BM25) scoring to pull the top‑k candidate passages from the live web index.

sim(q, c) = E(q)·E(c) / ‖E(q)‖‖E(c)‖
03

Cross‑encoder reranking

Each candidate is re‑scored jointly with the query for relevance, freshness and source authority. Thin, keyword‑stuffed or blocked pages fall out here.

r(q, c) = σ(W·[q ⊕ c])
04

Entity resolution and corroboration

Mentions are resolved to canonical entities through schema.org markup, sameAs links and knowledge‑graph IDs. An entity backed by many independent, mutually consistent passages gains confidence. Conflicting attributes, like two descriptions or two phone formats, split it into weaker fragments.

conf(e) ∝ Σ agree(ci, cj) − Σ conflict(ci, cj)
05

Grounded generation and answer calibration

The model writes from the retained context and names only entities above its confidence threshold. Every follow‑up ("which is cheapest," "which covers Texas") re‑retrieves against the same entity set, so each answer has to check out again.

P(name e | q, C) > θ

Our technique

Semantic Language Alignment

Most agencies optimize pages for keywords. We optimize the whole entity for retrieval. We lock one canonical statement of who Fresh is, measure how far every source on the web drifts from it in vector space, rewrite or republish the outliers, then seed new passages written in the semantic shape of the questions buyers actually ask: question‑first, entity‑first, cited and corroborated. Everything is bound to a single entity ID in schema, so AI resolves it all to one Fresh.

ALGORITHM SemanticLanguageAlignment(E, Q, S)
  input   E  the entity (Fresh Clinics USA)
          Q  target prompt set {q₁ … qₙ}
          S  every source that mentions E
  output  aligned corpus S*, publish plan P

 1  c   ← CanonicalStatement(E)  // locked
 2  v_c ← Embed(c)
 3  for each s ∈ S:
 4      drift(s) ← 1 − cos(Embed(s), v_c)
 5      if drift(s) > τ = 0.18 · w(authority(s)):
 6          Rewrite(s, c)  ∪  Normalize(NAP, schema, glossary)
 7  for each q ∈ Q:
 8      N_q   ← TopK(Embed(q), WebIndex, k)
 9      gap_q ← Σ max(0, sim(q, n) − sim(q, S*)) · λ_src(n)
10      P     ← P ∪ Generate(q, c, gap_q, format = Q→A→cite)
11      Distribute(P, channels ∈ {PR, video, guides, profiles})
12  Bind(S*, sameAs(E), schema:Organization)
13  repeat monthly until conf(E | q) > θ  ∀ q ∈ Q
